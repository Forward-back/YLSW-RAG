# Stage_3 错误根因与修复记录

全量 120 题端到端评测（DeepSeek 裁判）暴露 9 道错误、8 道部分正确，归为四类问题。本文记录每类问题的根因定位与修复方案。

## 一、错误分类与根因

### 1. "知识库有答案却回答未找到"（5 道错误 + 多道部分正确）

**现象**：检索层 hit@10 已命中正确 chunk，甚至正确 chunk 排在重排链第 1/2 位，生成层仍回答"抱歉，未找到与您问题相关的信息"。

**根因分两层**：

- **生成层放弃（3 道）**：BASE_PROMPT 的拒答条件过松（"资料中完全没有任何相关信息"），LLM 面对难匹配问题倾向放弃作答。
- **检索层丢弃（银联 APP 授权登录题，1 道）**：`planner.py` 的 `_light_retrieve` 过滤候选时只保留 `corpus`/`sql` bucket，把 metadata 命中的候选丢弃。该题正确 chunk 被 meta 检索命中（云闪付产品 label），却在过滤环节被扔掉，导致重排输入全是无关新闻 chunk。
- **LLM 随机性（小U集团题）**：temperature=0.1 下同一题时对时错，提示词收紧后趋于稳定。

**修复**：
- `src/retrieval/planner.py`：`_light_retrieve` 候选过滤放行 `metadata` bucket。
- `src/llm/generator.py` BASE_PROMPT【拒答处理】重写：判断标准改为"主题完全无关"；只要参考资料与问题存在任何实体重叠（产品名、机构名、文号、表名、字段名、年份）就必须作答；新增"不确定时选择作答"倾向性规则。

### 2. 时间限定不清（2 道错误）

**现象**：外汇风险准备金两题。一题问 2022 年 9 月 26 日通知下的准备金率，系统称"未找到该通知内容无法确认"；另一题 2017 年 207 号文与 2018 年 190 号文混用，把"应交"答成"无需交"。

**根因**：
- 规划器改写 step query 时没有保留时间/文号限定的硬性规则，检索语义被稀释。
- 生成层对同一主题多版本文档没有逐份核对文号的要求。

**修复**：
- `src/retrieval/planner.py` PLANNER_PROMPT 新增规划规则 4：step query 必须完整保留时间限定与文号，严禁丢弃或泛化。
- `src/llm/generator.py` BASE_PROMPT 新增【时间核对规则】：多版本（多年文、多版手册）必须逐份核对文号/时间，只引用与问题时间限定一致的版本；引用法规必须写明文号。

### 3. 数值计算不准确（2 道错误）

**现象**：9 家支付公司营收之和 83.5661 亿元被算成 88.5651 亿元、占比 0.48% 写 0.45%；数字人民币试点钱包数 4490+2515.9+3000=10005.9 被加成 13005.9。

**根因**：LLM 对多分量求和/百分比直接心算，无计算纪律约束；数据查询标签的红线"资料没有的数值绝不推算"被 LLM 误读为"不鼓励计算"。

**修复**：
- `src/llm/generator.py` BASE_PROMPT 新增【数值计算规则】：求和/求差/百分比必须列完整算式再给结果，严禁心算；计算后自查代回核对；数值逐位照抄。
- `src/prompts/数据查询.json` 新增【数值计算】段 + 红线补注："资料给出分量时，求和/求差属于应做计算，不算凭空推算"。

### 4. Excel 表理解不足（2 道错误）

**现象**：
- 清分交易汇总信息表（BASE_QF_T_TRANS_DAY_HIS）字段勾稽校验题（MER_FEE 是否等于四项之和）答"未找到"。
- 基础信息统计表收费站计数差题（京珠运营公司收费站数 − 襄阳运营公司收费站数）答"未找到"。

**根因**：
- 清分表在库中只存字段字典（无真实交易数据），字段勾稽关系在语料 chunk 中，LLM 面对字段字典类问题放弃作答（同问题 1 的生成层根因）。
- 计数题走 planner multi_hop 拆分，SQL 引擎无计数模板，只返回 DISTINCT 公司名单，LLM 面对名单算不出计数差。
- 两条 SQL 查询结果（各公司计数）的候选 chunk_id 恒为 -1，在候选合并去重时互相覆盖，丢失一半结果。

**修复**：
- `src/retrieval/text_to_sql.py` 新增 `_try_count_template` 计数模板（"数量/多少个/几个" + 公司名 → COUNT GROUP BY），并置于 DISTINCT 模板之前优先命中。
- `src/retrieval/planner.py` 两处候选合并去重键修复：sql 候选（chunk_id=-1）的键带上 step id / item 名，避免多个表格查询结果互相覆盖。
- `src/prompts/数据查询.json` 新增【字段与表格】段：字段定义与勾稽关系题必须逐字段引用资料说明，字段名原文引用。

## 二、修复验证（全量 120 题重跑）

**整体**：正确率 86% → **92.5%**（103 → 111 道正确），错误 9 → **1**，部分正确 8。含部分正确 99%。

| 题型 | 修复前正确率 | 修复后正确率 |
|---|---|---|
| 单文档 | 93% | 97% |
| 多文档-并行 | 67% | 67%（0 错误，4 部分） |
| 多文档-串行 | 75% | 83% |
| 数值计算 | 58% | 92% |
| 安全类 | 100% | 100% |

**单题复测**

| 题目 | 修复前 | 修复后 |
|---|---|---|
| 云闪付 APP 授权登录 signature 签名因子 | 未找到 | 签名因子：appId、secret、nonceStr、timestamp；expiresIn：7200秒 |
| 清分交易表 MER_FEE 勾稽校验 | 未找到 | ACQ_SHR_AMT=1.00；四项和 15.00=MER_FEE |
| 基础信息统计表收费站计数差 | 未找到 | 京珠 55、襄阳 38、差 17 |
| 9 家支付公司营收求和 | 88.5651（错） | 83.5661（对，带算式） |
| 银监会客户风险信息 3 个工作日 | 未找到 | 3 个工作日内印发核实表 |
| 设备更新补贴标准 | 未找到 | 新能源 2 万 / 燃油 1.5 万 + 旧车范围 |
| 消费篮子材料B | 未找到 | 20 个百分点 / 68.3% / 两种思路 |

**剩余 1 道错误**：商圈魔盒题 LLM 编造参考依据未提及的服务（积分领取、停车抵扣、消费开票）。部分正确 8 道为编造补充信息、覆盖不全、时点表述、求和尾差。

**第二轮修复（检索链 + 上下文组装层）**

| 根因 | 修法 |
|---|---|
| `_dedup_by_latest_version` 按文档组聚合重排，多文档题后组候选被挤出 top-K | 去重改为保序输出（按原始顺序过滤） |
| 上下文去重 span 覆盖判定对 child 局部文本误判覆盖 | 仅完整 parent/union 文本条目可作为覆盖证据（`full` 标记） |
| 语义检索漏召相邻条款块（补贴标准分段） | 检索层邻域扩展 `_expand_siblings`（±2 相邻块补入融合池）+ 重排后邻域补全额度 8 |
| planner 轻检索规模不足（top-8） | STEP_FAISS_K 20→30、STEP_TOP_K 8→12 |
| Rerank 输入裁剪 50 条 | RERANK_MAX_CANDIDATES_PER_SOURCE 50→100 |
| LLM 结论与论据矛盾 | 提示词【结论自查规则】：判断题结论必须从依据直接推出 |
